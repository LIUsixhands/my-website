# 🧲 AI 員工「小增」— 保險增員／人力招募專員　安裝與使用說明

> Sixhands Studio AI數字員工　🦞
> 這位員工只做一件事：**讓「跟我當初聽到的不一樣」這句話不再出現。**
> 他不保證收入、不保證考取、不設年齡性別條件、不收求職者一毛錢。
> 他做的是**人才畫像、增員名單、招募說明會、面談評估、誠實揭露、考照時程、90 天育成、定著分析**。

## 一、安裝（三分鐘，Mac／Windows 都一樣）

### Mac
```bash
cp -R ~/Desktop/AI員工_小增 ~/.claude/skills/skill-xiao-zeng
```
重開 Claude Code，輸入 **「小增」** 測試。

### Windows
整個資料夾放到 `C:\Users\你的帳號\.claude\skills\skill-xiao-zeng`，其餘相同。

## 二、第一次使用的順序（照做，不要跳）

```
1. 打「小增」
2. 回答身分三題
     ① 你是保險公司主管還是保經代主管？公司全名？
     ② 登錄字號？有沒有報聘權限？
     ③ 你們的招募文宣要送誰審？流程多久？
3. 填 templates/招募主管資料卡.json（九項誠實揭露欄位）
4. 打開 references/待補15題.md，一次問完、填完
5. 小增才會開始出第一份文件
```

🚨 **第 11、12 題問不到，就先不要開始增員。**
（單位近一年新人到職／滿 3 個月／滿 13 個月各幾人；新人前三個月實際收入區間、其中幾人是 0）
問不到，代表這個單位沒有在追蹤留存 —— 人送進去也是漏掉，先把這兩個數字建起來。

## 三、八個指令（在 skill 資料夾底下跑）

```bash
python3 scripts/zeng.py init                          # 在目前資料夾產出全部範本
python3 scripts/zeng.py pipeline 增員名單表.csv        # 名單池體檢：誰停滯了、哪個來源真的變成人
python3 scripts/zeng.py funnel   增員漏斗表.csv        # 漏斗卡在哪一段、反推要多少名單
python3 scripts/zeng.py score    面談評估表.json       # 七維度評分＋四條硬性門檻
python3 scripts/zeng.py disclose 招募主管資料卡.json   # 誠實揭露包（沒填就標「待補」，不編數字）
python3 scripts/zeng.py plan90   --name 阿凱 --start 2026-09-15
python3 scripts/zeng.py retention 增員名單表.csv       # 定著率、死在第幾個月、脫落原因
python3 scripts/zeng.py check    招募貼文.md           # 交件前必跑 → 紅字＝不准交件
```

`check` 有紅字時會以 exit code 2 結束 —— 這是故意的，讓它可以擋自動化流程。

## 四、跟「小安」「小顧」「小招」怎麼分

| 你要做的事 | 找誰 |
|:---|:---|
| 吸引**客戶**：貼文、短影音、約訪、轉介 | **小安**（保險行銷） |
| **客戶**坐下來了：盤保單、算缺口、陪理賠 | **小顧**（保險顧問） |
| 找**業務員**：名單、說明會、面談、育成、定著 | **小增**（本員工） |
| 課程招生、開班行政 | 小招（不同的「招」，別叫錯） |

三隻保險員工可以一起用：小安帶客戶進門，小顧服務客戶，小增找人。

## 五、🚨 四件事一定要記住

1. **小增的產出都是「草稿」。** 送所屬公司／保經代審查核可之後，才可以對外。
2. **十二條紅線**（見 `references/增員合規紅線.md`）最常踩的四個：
   保證收入、年齡性別條件、收保證金押證件、叫同業把客戶名單帶過來。
3. **誠實揭露包要在第二次面談就攤開**，不是報聘後才講。
   它會讓你的漏斗前段變窄、後段變寬 —— 那是省下來的時間，不是損失。
4. **名單裡是「還沒錄取的人」的個資。** 一律用代號、放本機碟（不要 iCloud 桌面）、
   未錄取者定期銷毀；評估表不得寫年齡、性別、婚姻、容貌、星座、血型。

## 六、遇到問題

- 指令跑不動 → 確認有裝 Python 3（終端機打 `python3 -V`）
- 中文變成問號 → 用 UTF-8 存檔
- CSV 改完沒生效 → 存檔時選「UTF-8 CSV」，不要用 Big5
- 不確定某句話能不能寫 → 丟給 `zeng.py check`，再對照 `references/增員合規紅線.md`
