## 🚧 開工前必讀：三條硬規（寫死在程式裡，不是建議）

1. **沒有 `--confirm` 絕不刪任何東西。** `reclaim` 永遠唯讀，`clean` 不加旗標就是 dry-run。
2. **刪中間檔前必須驗到成品。** 認定標準刻意收緊：成品要嘛在 `final/` `output/` `成品/` 這類交付資料夾內（>1MB），要嘛是 ≥20MB 的影片／文件。**驗不過就鎖住（🔒），小健不自己解鎖。**
   > 這條是踩出來的：早期版本把任何 >1MB 媒體檔都當成品，結果 `narration/ch3.mp3`（旁白素材）也被當證據放行——守門形同虛設。
3. **黑名單永不觸碰**：Claude 沙箱 VM（`vm_bundles`，13GB，刪了 Bash 沙箱直接掛）、對話紀錄（`claude-code-sessions`）、金鑰（`.ssh` `.gnupg` `Keychains`）。掃都不掃。


## 📋 標準工作流：有人說「電腦很慢」怎麼做

### 第 1 步：先 `scan`，不要先猜
三個指標一起看，**慢的原因通常不是你以為的那個**：

| 指標 | 🟢 健康 | 🟠 注意 | 🔴 危險 |
|---|---|---|---|
| 磁碟可用 | >15% | 10–15% | **<10%** |
| Swap 使用 | <50% | 50–80% | **>80%** |
| 可用記憶體 | >40% | 25–40% | **<25%** |
| load ÷ 核心數 | <70% | 70–100% | **>100%** |

### 第 2 步：認出連鎖反應
這三項會互相拖累，**先修磁碟**：
> 磁碟滿 → swap 檔擠不大 → 記憶體壓力無處宣洩 → 壓縮器狂轉 → 回頭吃 CPU → load 飆高

2026-09-14 實例：磁碟 94% 滿 ＋ swap 93% ＋ load 112%，清完磁碟後三項一起回到綠燈。

### 第 3 步：`reclaim` 看可回收清單（**不會刪東西**）
輸出分三區：✅ 可安全回收（附成品證據）／🔒 鎖住不刪／🟡 快取（會自動重建）。
**把清單給人看過再往下走。**

### 第 4 步：`clean --confirm` 刪，然後複驗
刪完一定要複驗成品數量。今天的做法：
```bash
ls -1 ~/Desktop/專案/*/final/*.mp4 | wc -l    # 刪除前後對照
```

### 第 5 步：記憶體要真的拿回來，只有一招
🚨 **封存舊工作階段不等於釋放記憶體。** 2026-09-14 實證：封存 4 個舊 session，`claude` 活行程數 42→42，**完全沒動**。舊 session 早就沒有活行程了，封存只是清單變乾淨。

真正有效的做法是 **`Cmd+Q` 完全結束 Claude App 再重開**（不是關視窗）。所有對話都存在硬碟上，重開後從側邊欄點回去，不會掉內容。實測 42 個行程 → 3 個，記憶體回來 3.3GB。

**關掉前務必先確認沒有排程正在跑**（`isRunning: true` 的工作階段）。

### 第 6 步：交付健檢報告
用 `templates/健檢報告.md`，一定要有**前後對照表**——數字才是證據。
