# 踩雷速查

## 🚨 假訊號：封存工作階段 ≠ 釋放記憶體
2026-09-14 實測：封存 4 個舊 session，`claude` 活行程數 **42 → 42，完全沒動**。
原因：那些 session 最後活動在 4–5 天前，早就沒有活行程；封存只是清單變乾淨。

**吃記憶體的是活行程，不是 App 裡的分頁清單。** 判斷一律看：
```bash
ps -Aceo comm | grep -c '^claude$'
```
要一次拿回全部記憶體，唯一有效做法是 **`Cmd+Q` 完全結束 App 再重開**（不是關視窗）。
對話都存在硬碟，重開後從側邊欄點回去，不會掉內容。實測 42→3 個行程，回收 3.3GB。

⚠️ 關掉前先確認沒有排程正在跑（`isRunning: true` 的工作階段）。

## 🚨 swap 總量會自己伸縮 —— 別把它當成「誰刪了東西」
macOS 的 swap 檔是動態的。記憶體壓力解除後系統會自動把它收掉：
2026-09-14 觀察到 **8,192MB → 2,048MB**，磁碟因此「憑空」多出 6Gi。
這是系統確認壓力真的解除的**正面訊號**，不是有人刪了檔案。報告裡要講清楚，否則數字對不起來。

## 🚨 iCloud 桌面會搞死排程與腳本
讀桌面（iCloud）檔會噴 `EDEADLK` / `EPERM` / `Errno 60`，而且症狀是**間歇性**的。
腳本零輸出卡死時：先測 `open()` 再看 `cloudd`。**資料檔一律放本機路徑**
（像 `~/貓咪經濟學/` 那樣，不要放 `~/Desktop/`）。
見 [[feedback_icloud_dataless_breaks_launchd]]。

`perfcheck.py sched` 會自動標出路徑在 `/Desktop/` 或 `/Documents/` 的排程。

## 🚨 launchd 定時排程缺 RunAtLoad 會靜默不跑
`StartCalendarInterval` 在「那一刻 agent 還沒載入」（GUI 未登入）就**整個消失不補跑**。
症狀：log 零紀錄 ＋ `runs = 0`。治本：`RunAtLoad=true` ＋ 腳本冪等 ＋ 通知按天去重。
見 [[feedback_launchd_calendar_needs_runatload]]。

> 2026-09-15 小健首次 `sched` 掃描發現 **8 個排程 `RunAtLoad => 0`**，
> 含 `com.sixhands.daily-publish`、`com.poetic.daily-publish`、`com.sixhands.frozen.ep07dual`。

## 🚨 grep 在中文檔上配大量詞會卡死數分鐘
UTF-8 locale ＋ 多位元組 ＋ `{0,70}` 量詞三者齊發才觸發。加 `LC_ALL=C` 秒解。
症狀很像 iCloud 卡死，但 `cp`/`cat` 都正常、**只有 grep 卡**。
見 [[feedback_grep_utf8_quantifier_hang]]。

## 🚨 `du -sh ~/*` 會回傳 exit code 1 —— 那不是失敗
掃到沒權限的路徑就會回 1，但資料本身是完整的。別把它當錯誤處理掉。

## 🚨 成品可能不在專案根目錄
TFA 的成品在 `episodes/EPxx/final/`，不在 `episodes/EPxx/` 底下。
用 `ls 專案/*.mp4` 判斷「有沒有成品」會得到錯誤結論。**一定要遞迴找 `final/`。**
