# 判讀基準與紅線

## 門檻數字（寫在 perfcheck.py 的 `light()` 裡）

| 指標 | 取得方式 | 🟢 | 🟠 | 🔴 |
|---|---|---|---|---|
| 磁碟可用 % | `df -k /System/Volumes/Data` | >15% | 10–15% | **<10%** |
| Swap 使用 % | `sysctl -n vm.swapusage` | <50% | 50–80% | **>80%** |
| 可用記憶體 % | `memory_pressure` | >40% | 25–40% | **<25%** |
| load ÷ 核心 | `uptime` ÷ `hw.ncpu` | <70% | 70–100% | **>100%** |
| claude 活行程 | `ps -Aceo comm \| grep -c '^claude$'` | ≤8 | 9–20 | **>20** |

**為什麼磁碟是 10%**：macOS 低於 10% 就會出現 swap 無法擴張、Spotlight 反覆重建索引、
App 存檔失敗。這不是保守估計，是實際的行為轉折點。

## 連鎖反應（先修哪一個）
```
磁碟滿 → swap 檔擠不大 → 記憶體壓力無處宣洩 → 壓縮器狂轉 → 回頭吃 CPU → load 飆高
```
**永遠先修磁碟。** 2026-09-14 實例：磁碟 94% 滿時三項全紅；清出 16Gi 後三項一起回綠。

## 三條硬規

### 1. 沒有 `--confirm` 絕不刪
`reclaim` 永遠唯讀。`clean` 不加旗標就印 dry-run 清單然後退出。

### 2. 成品守門（最重要的一條）
刪任何專案的中間檔前，必須在該專案 tmp 以外找到**成品**：
- (a) 位於 `final/` `output/` `outputs/` `成品/` `交付/` `dist/` `publish/` `export/` `release/` 內，且 >1MB
- (b) 或不在交付資料夾，但 ≥20MB 的影片／文件

驗不過 ⇒ 標 🔒 鎖住，**小健不自己解鎖**，要刪必須人工確認成品位置。
`clean --confirm` 執行時會**再驗一次**才動手（雙重保險）。

> 🚨 這條是踩出來的。早期版本只要求「>1MB 的媒體檔」，結果 `narration/ch3.mp3`
> （旁白素材，2.6MB）被當成品證據放行。那是中間素材不是成品 —— 守門形同虛設。

### 3. 黑名單永不觸碰
| 路徑 | 為什麼 |
|---|---|
| `Library/Application Support/Claude/vm_bundles` | Claude Code 沙箱 VM，13GB。刪了 Bash 沙箱直接掛。要省只能去設定關沙箱模式 |
| `Library/Application Support/Claude/claude-code` | 執行檔本體 |
| `Library/Application Support/Claude/claude-code-sessions` | 所有對話紀錄 |
| `Library/Keychains` `.ssh` `.gnupg` | 金鑰 |
| `Library/CloudStorage` | 雲端同步掛載點 |

## 可回收的中間檔樣式（白名單）
只有名字符合這些的**資料夾**會被列入回收候選，永不碰單一檔案：
```
tmp  temp  tmp_v1 tmp_v2 …  tmp_shorts  tmp_shorts2  tmp_thumb
*_tmp  once_tmp  once2_tmp  nostatic_tmp
```
