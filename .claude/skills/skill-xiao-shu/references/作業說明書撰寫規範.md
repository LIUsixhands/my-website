# 作業說明書撰寫規範（小書專用）

## 一、文件標準結構

```
封面        文件名稱／版本／日期／維護人／適用對象＋ logo
1. 目的     為什麼有這份文件（一段話）
2. 適用範圍 誰要做、什麼情況下做、什麼情況不適用
3. 事前準備 帳號權限、需要的檔案、需要的資訊（做成 checklist）
4. 操作步驟 主體：一步一圖
5. 例外處理 失敗／跳錯誤／資料不齊時怎麼辦
6. 驗收標準 怎樣算做完做對
7. 常見問題 Q&A（第二版以後才會有內容）
8. 名詞對照 系統術語 ↔ 白話
9. 變更紀錄 版本／日期／改了什麼／為什麼／誰改的
附錄       ❓待確認清單
```

## 二、寫作鐵律

1. **一步一動作，一步一圖。** 一張圖要做三件事 → 拆成三步，圖裁三次。
2. **祈使句、動詞開頭。** 「點選左上角『新增』」；不要「使用者需要進行新增之動作」。
3. **稱呼用「你」。** 不用「使用者」「操作人員」。
4. **描述長相，不只寫功能名。** 「畫面右上角的藍色『送出』按鈕」勝過「送出功能」。
5. **禁用模糊詞：** 應該、大概、基本上、原則上、盡量、視情況。出現＝你不確定＝該去問。
6. **每步都要有判斷點。** 看到什麼算成功、看到什麼要轉走。
7. **分歧寫成明確跳轉。** `若顯示「查無資料」→ 跳至 §5.2`。
8. **數字、欄位名一字不改照抄畫面。** 民國年就寫民國年。
9. **時間感。** 標「約 30 秒」讓人知道是慢還是當掉。
10. **不寫個人化資訊。** 「找王小明簽」→「找該案負責主管簽」（人會離職，文件不會跟著改）。

## 三、圖說規範

- 每張圖都要有編號與圖說：`圖 3｜訂單建立畫面，紅框處為必填欄位`
- 重點一律**紅框**標示；順序用 ①②③ 圓圈數字
- 一張圖最多標 3 個重點，超過就拆圖
- 螢幕截圖裁掉瀏覽器書籤列、桌面背景、其他分頁
- **去識別化必做**：姓名、電話、Email、身分證、帳號、金額、地址、密碼欄
- 圖片寬度建議 ≥ 1200px，文字要看得清楚；太小就重截，不要放大糊掉

## 四、版本控管

- 版本號 `v主.次`：次版＝文字修正／補圖；主版＝流程本身改了
- 流程一變，**當天**改文件；來不及就先在受影響步驟加一行 `⚠️ 2026-08-30 起改為…`
- 變更紀錄永遠往上加，不覆蓋舊列
- 舊版本移到 `輸出/舊版/`，不刪除（稽核會問）

## 五、常見翻車點

| 現象 | 根因 | 解法 |
|:---|:---|:---|
| 新人照做卡在第 4 步 | 缺前置條件（權限沒開） | 「事前準備」補 checklist |
| 每個人做出來的結果不一樣 | 缺判斷點與驗收標準 | 每步補判斷點，補 §6 |
| 文件沒人看 | 太長、找不到重點 | 主流程壓在 1-2 頁，細節丟附錄 |
| 圖跟畫面對不上 | 系統改版沒改文件 | 變更紀錄 + 每季複查 |
| 圖看不清楚 | 手機拍螢幕、縮圖放大 | 一律用系統截圖，不用相機拍 |
