# 片頭偵測原理 — 為什麼不能用固定秒數

## 實測數據（Kelly 華語聽力教材，2026-09-13）

| 檔案 | 片頭結構 | 切點 |
|---|---|---|
| 04_L1-4 習作-看圖辨義 | **10 秒音樂** ＋「現在開始聽力作業第一部分，看圖辨義」 | 17.22s |
| 05_L1-5 習作-問題 | 無音樂，直接「現在開始聽力作業第二部分，問答」 | 5.27s |

**同一套教材、同一個錄音室、同一個配音員，片頭差 3.3 倍。**
用固定秒數批次切，一定會有檔案被切掉題目、或有檔案留著半句導語。

## 三段式偵測

### 1. Whisper 辨識前 60 秒
逐句判斷是「片頭」還是「內容」：
- 命中 `INTRO_PAT`（現在開始／聽力作業／第X部分／問答／看圖辨義…）且**不含連續 3 個英文字母** → 片頭
- 命中 `HALLU_PAT`（字幕志願者／請不吝點贊訂閱／Amara…）→ **純音樂或雜訊段**
  （Whisper 對非語音會產生這類固定幻覺句，正好可以當「這裡不是人聲內容」的訊號）
- 第一句都不命中的 → 正式內容起點

### 2. 靜音偵測對齊
Whisper 的 word timestamp **會往前漂 0.5～1 秒**（實測 04 檔：Whisper 說內容在 16.88s，
實際語音起點是 17.52s）。直接用 Whisper 的時間會把第一個字切掉一部分。

所以改用：`silencedetect` 找出所有靜音區間，取**「片頭結束之後的第一段靜音」的結束點**，
那就是正式內容第一個字真正開始的位置。

```
cand = first_content["start"]
for a, b in sils:
    if a >= intro_end - 0.5:
        cand = b
        break          # ← break 很重要
```

> 🚨 **這裡踩過坑**：第一版沒有 `break`，而是用 `b <= cand + 2.5` 當條件繼續掃。
> 因為 `cand` 在迴圈內被自己更新，容忍區間跟著往後滑，切點滑到「第一題題號唸完之後」的停頓，
> 把整句「Number six.」吃掉了。**症狀是指令完全沒報錯**，只有聽成品才發現。

### 3. 留 pad
最後 `cut = cand - 0.30`，留 0.3 秒緩衝，聽起來才不會像被硬切。

## 沒有 Whisper 時
退化成純靜音啟發式：取第一段靜音的結束點。這個結果**一律標為低信心**，
`trim` 預設跳過，必須人工確認或 `--force`。
