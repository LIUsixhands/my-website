# 巡檢 19 項｜在檢查什麼・怎麼判讀・怎麼修

> 工具會給判定，但**判讀是人的工作**。這份文件是小維的判讀依據。

## A. 網站還活著嗎（客戶最在意的）

| 項目 | 在查什麼 | 判失敗代表 | 怎麼修 |
|---|---|---|---|
| 可用性 | HTTP 狀態碼 | 0＝DNS/主機死；4xx＝路徑錯；5xx＝伺服器爆 | 見《故障排除手冊》 |
| 載入速度 | 首頁回應毫秒 | >2s 偏慢、>4s 跳出率暴增 | 圖片轉 WebP、加 `loading="lazy"`、砍未用外部字型 |
| HTTPS | 是否走加密 | 瀏覽器標「不安全」，客戶不敢填表單 | Netlify/GitHub Pages 開強制 HTTPS |
| SSL 憑證 | 到期日 | 過期＝整頁紅色警告，等於關店 | 剩 <21 天就查自動續期有沒有壞 |
| 網域到期 | whois 到期日 | 過期會被搶註，網址永久失去 | 剩 <45 天提醒客戶續約＋開自動續約 |

**免費子網域**（netlify.app / github.io / vercel.app）無需續約，工具標 ℹ️。
但要提醒客戶：**免費子網域不是資產**，客戶付費做的品牌官網應該綁自己的網域。

## B. 找得到嗎（SEO）

| 項目 | 標準 | 備註 |
|---|---|---|
| `<title>` | 30 字內，格式「品牌｜主要服務｜地區」 | 超過會被搜尋結果截斷 |
| meta description | 60–80 字，含服務＋地區＋行動呼籲 | 缺了 Google 會亂抓內文 |
| `<h1>` | 每頁一個，寫主要服務不是寫「首頁」 | 沒有 H1 是常見疏漏 |
| html `lang` | `zh-Hant-TW` | 影響搜尋地區判定與瀏覽器翻譯提示 |
| favicon | 有設定 | 沒有＝分頁一片空白，看起來像沒做完 |
| 圖片 alt | 過半有 alt | SEO＋無障礙，圖片壞掉時也有替代文字 |

## C. 會帶來生意嗎（轉換）— 最容易被忽略、也最貴

| 項目 | 為什麼重要 |
|---|---|
| **聯絡管道** | 電話／LINE／Email／表單至少一個。一個都沒有＝這網站不會帶來任何生意，網站做假的。 |
| **手機版 viewport** | 沒設定的話手機整頁縮小到看不清，而 7 成以上流量來自手機。 |
| **混合內容** | https 頁面載 http 資源，瀏覽器直接擋掉，畫面破圖或功能失效。 |
| **失效連結** | 點了沒反應的客戶不會回頭。社群平台回 4xx 是擋機器人，要人工確認。 |

⚠️ **表單能送出 ≠ 有收到**。工具只檢查表單存在，**每月必須人工實測送一筆**，確認信箱／後台真的收得到。表單靜靜壞掉三個月是維運最經典的災難。

## D. 內容還正確嗎（維運真正的價值）

| 項目 | 抓什麼 |
|---|---|
| **過期日期** | 頁面上早於今天的寫死日期。活動頁最常見的死法。⚠️ 只抓得到文字，**圖片上燒死的日期必須人工目視** |
| **必載內容** | 客戶清冊 `must_contain` 指定的關鍵資訊（營業時間、證號、退費規定…）消失就告警，多半是改版時被覆蓋 |
| **佔位殘留** | 待補／TODO／Lorem／假電話／範例信箱上線 |
| **合規禁字** | 依產業比對禁用字，見《合規稽核規則》 |

## E. 分數怎麼算
`100 − FAIL×12 − WARN×4`（最低 0）
- **90 以上**：健康，月報寫「本月無重大異常」
- **70–89**：要處理，列改善清單
- **70 以下**：急件，當天聯絡客戶

分數是給客戶看的溝通工具，**不是決策依據**。一個 96 分但表單壞掉的站，比 70 分但一切能動的站嚴重得多。
