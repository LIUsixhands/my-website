## 🧰 工具：`webcheck.py`（零依賴，純標準庫）

位置：`~/.claude/skills/skill-xiao-wei/scripts/webcheck.py`
工作區：`~/AI員工_小維/`（**本機碟，不可放桌面 iCloud** — 見 [[feedback_icloud_dataless_breaks_launchd]]）
客戶清冊：`~/AI員工_小維/clients/sites.json`

```bash
cd ~/.claude/skills/skill-xiao-wei/scripts

python3 webcheck.py check <網址或客戶代號>      # 單站全項健檢（19 項）
python3 webcheck.py scan                         # 全客戶巡檢＋總表排序
python3 webcheck.py scan --client chichaka       # 指定單一客戶
python3 webcheck.py links <網址> --max 100       # 連結失效掃描
python3 webcheck.py cert <網域>                  # SSL 憑證 + 網域到期
python3 webcheck.py audit <網址> --industry medical   # 合規稽核
python3 webcheck.py snap <客戶代號>              # 拍內容快照（建基準）
python3 webcheck.py diff <客戶代號>              # 比對是否被動過手腳
python3 webcheck.py report <客戶代號>            # 產出當月月報 Markdown
python3 webcheck.py industries                   # 列出 9 種產業合規規則
```

### 檢查的 19 項
可用性／載入速度／HTTPS／SSL 憑證到期／網域到期／SEO 標題／SEO 描述／viewport 手機版／html lang／H1／favicon／圖片 alt／混合內容（https 頁面載 http 資源）／**聯絡管道是否還在**／**過期的寫死日期**／客戶指定必載內容／**產業合規禁字**／**佔位殘留（待補、TODO、Lorem、假電話）**／失效連結。

### 判定等級
- ❌ **FAIL**：法律紅線或功能壞掉，**必修**
- ⚠️ **WARN**：修辭風險／改善建議，**人工判斷**
- ℹ️ **INFO**：社群平台擋機器人、免費子網域等，**不是問題**

**⚠️ 工具是助手不是法官**：禁字命中要人工看上下文（餐廳寫「白飯殺手第一名」是修辭，不是不實廣告），別把機器報告直接丟給客戶。

## 📋 SOP 一：每月例行巡檢

1. `python3 webcheck.py scan` 跑全清冊，**先看總表排序**，紅燈優先。
2. 紅燈站逐一 `check` 看細節，判斷「真問題 vs 誤報」。
3. `diff <客戶代號>` 比對內容有沒有被動過（客戶自己改壞 / 被入侵掛馬）。
4. 分三類處理：
   - **我能直接修**（錯字、失效連結、過期日期）→ 修完部署，寫進月報
   - **要客戶決定**（改價格、換方案、加內容）→ 列進月報「待客戶確認」
   - **要小網重做**（版型爛掉、架構過時）→ 月報建議欄，附改版理由
5. `report <客戶代號>` 產月報 → 套 `templates/維運月報.md` 補人話說明 → 掛品牌 logo → 交付。
6. 更新 `snap` 快照當下個月基準。

## 📋 SOP 二：緊急故障（網站掛了）

**五分鐘定位順序，不要跳步：**
1. `webcheck.py check <網址>` → 看是 HTTP 幾號。
2. **連不上（狀態 0）** → 是 DNS 還是主機？`nslookup <網域>`、`ping`。網域到期是最常見原因，`webcheck.py cert` 一秒確認。
3. **HTTP 4xx** → 部署路徑或首頁檔名錯了。Netlify 查 deploy log、GitHub Pages 查 Settings→Pages 分支。
4. **HTTP 5xx** → 主機／函式錯誤，查平台 log。
5. **憑證紅色警告** → 憑證過期或網域綁定跑掉，重新簽發。
6. **打得開但空白** → JS 錯誤，開瀏覽器 console 看。
7. 修好後**一定要重新整理實際頁面驗證**，不能只憑「我改好了」回報。
8. 事後寫一則 memory 記錄根因，避免同一個坑踩兩次。

## 📋 SOP 三：內容變更工單

1. 用 `templates/變更工單.md` 收單 — **要客戶用文字寫清楚改成什麼**，不接受「你看著辦」。
2. 改動前先 `snap` 拍快照（改壞了有得回頭）。
3. 找源碼：查客戶清冊 `source` 欄位 → 改本機檔 → **重新部署**（改本機不會自動上線）。
4. 部署後 `check` 一次，確認沒改壞別的地方。
5. 回報客戶：附「改了什麼 + 網址 + 截圖」。

## 📋 SOP 四：上線前必查（幫小網把關）

小網新站要上線前，小維跑一次守門：
```bash
python3 webcheck.py check <預覽網址> --industry <產業>
```
**四項一票否決，任一項沒過不准上線：**
1. 佔位殘留（待補／TODO／假電話／Lorem）＝ 0
2. 合規 FAIL 級禁字 ＝ 0，法定必載欄位齊全
3. 聯絡管道至少有一個（沒有轉換出口＝這網站不會帶生意）
4. 手機版 viewport 有設定

## 🚨 紅線（不可逾越）

1. **未經客戶書面同意，絕不改動線上內容。**錯字這種顯而易見的可先修後報備；價格、方案、聯絡方式、法律文字**一律先問**。
2. **絕不經手客戶金流、後台管理員密碼、網域註冊商帳號密碼。**需要改設定就開會請客戶自己操作，或請客戶開權限最小的協作者帳號。
3. **絕不承諾「100% 不當機」「保證不被駭」「保證 SEO 第一頁」。**只承諾「發現問題後 X 小時內回報並處理」。
4. **合規稽核只做提示，不做法律意見。**判定為法律爭議時轉 `skill-xiao-bian`（小辯）。
5. **客戶網站的品牌是客戶的**，不強掛龍蝦 logo（[[feedback_b2b_client_mv_no_lobster_logo]]）；只有**交給客戶看的巡檢報告／月報**掛Sixhands Studio品牌。
6. **禁止刪除任何檔案或 repo。**還原一律靠快照與版控，不靠 `rm`。
7. **絕不把客戶網站原始碼、後台網址、清冊內容貼給第三方服務。**

## 🩹 踩雷記錄（維運血淚，每次巡檢前必看）

1. **中文網址會讓爬蟲直接噴 `UnicodeEncodeError`** — Google Maps 查詢連結最常見。`webcheck.py` 已內建 `encode_url()` 做 IRI→URI 轉換；自己另外寫腳本時記得補。
2. **Facebook / m.me / Instagram 對機器人一律回 400** — 這**不是**失效連結。工具已標成 ℹ️ INFO，但社群連結一定要**人工點開確認一次**，因為粉專改名／關閉是真的會發生。
3. **活動頁最常見的死法是「日期過了還掛在首頁」** — 且素材圖上的日期是燒死的，光改文案沒用（[[feedback_workshop_session_takedown_checklist]]）。工具的「過期日期」檢查只抓得到文字，**圖片上的日期必須人工目視**。
4. **佔位文字會活到線上** — `［待補：…］`、`TODO`、假電話上線後沒人發現。2026-08-29 首次巡檢就在 `ai-soul-lobster.netlify.app` 抓到 3 個學員見證佔位卡片直接對訪客顯示（連「不要寫收入數字」這種給自己看的指示都印出去了）。上線前必查第 1 項就是為此存在。
5. **改本機檔案不會自動上線** — 靜態網站一定要重新 push / 上傳 / deploy，改完必重新整理實際頁面驗證（[[project_lobster_workshop_site_deploy]]）。
6. **同名網站資料夾會拿錯** — 部署前先對檔案清單再送（講座網站來源是 `~/Desktop/講座報名網站_上線用/`，不是 `Sixhands Studio/website/`）。
7. **Browser pane 隱藏時截圖全白** — 那是空白圖層不是排版壞掉，別誤判成網站爛掉（[[feedback_browser_pane_hidden_screenshot_blank]]）。
8. **繁體字型用 Songti TC 不要用 SC** — SC 缺繁體字會渲染成空白（[[feedback_songti_tc_for_traditional]]）。
9. **grep 掃中文頁面配大量詞會卡死數分鐘** — 加 `LC_ALL=C` 秒解（[[feedback_grep_utf8_quantifier_hang]]）。
10. **客戶自己改網站是常態，不是意外** — 所以 `snap`/`diff` 要養成每月跑的習慣，法定必載欄位被刪掉這種事，只有比對才抓得到。
