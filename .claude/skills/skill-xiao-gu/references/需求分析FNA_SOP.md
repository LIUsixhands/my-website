# 需求分析（FNA）與建議書草稿 SOP

## 一、FNA 六步（順序不可跳）

| 步驟 | 做什麼 | 產出 |
|:--|:---|:---|
| 1. 蒐集 | 家庭結構、收入支出、負債、既有保單、社會保險、健康狀況、既有資產 | `客戶資料卡.json` |
| 2. 確認目標 | 客戶自己說出「最擔心什麼」「最想保護誰」 | 面談紀錄表 |
| 3. 盤點現況 | 現有保障六大類別彙總 | `gu.py audit` |
| 4. 分析缺口 | 責任法＋倍數法雙軌 | `gu.py gap` |
| 5. 排序 | 依「風險發生後對家庭現金流的破壞力」排序，不依佣金排序 | 保障地圖 |
| 6. 說明與紀錄 | 說明假設、揭露限制、記錄客戶決定 | 建議書草稿＋紀錄 |

⚠️ **第 4 步之前不談商品。** 客戶一開口就問「哪張最好」，先回：「先看你已經有什麼、缺什麼，再看要用什麼補。」

## 二、建議書草稿的固定結構（八段）

1. **封面** —— 所屬公司全名／顧問姓名／登錄字號／日期／「草稿・未經審查不得交付」
2. **你目前有什麼** —— 六大類別現有保障彙總（客戶看得懂的話）
3. **你家的責任長什麼樣** —— 負債、教育、生活、奉養（數字＋假設）
4. **缺口在哪** —— 六大類別現有 vs 需求，用長條或表格
5. **建議的補強順序** —— 只寫「**保障類別＋需求額度區間＋優先順序＋為什麼是這個順序**」
6. **預算討論** —— 可負擔保費區間、繳費可持續性提醒
7. **限制與揭露** —— 四段揭露（＋解約損失揭露，如涉及調整）
8. **下一步** —— 「由顧問依公司商品規則提供可行方案並試算，最終以核保結果為準」

### 🚨 第 5 段的寫法（這一段最容易踩線）

| ❌ 不可寫 | ✅ 改成 |
|:---|:---|
| 建議投保 ○○人壽 ○○終身醫療 | 建議補強「住院日額」保障，需求區間約 ○,○○○ 元／日 |
| 這張最划算，CP 值最高 | 同類保障之保費依年齡、體況與商品規則而異，以核保結果為準 |
| 年繳 ○ 萬保證領回 ○ 萬 | （整段刪除，不做給付數字承諾） |
| 這張比 ×× 公司好 | （不做跨公司比較） |
| 買這張可以節稅 | 稅務效果因個案而異，以稽徵機關及稅務專業人員意見為準 |
